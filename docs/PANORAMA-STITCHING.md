# Panorama stitching

Select **2 to 64 overlapping photos** in the grid, open the context menu, and choose **Stitch panorama**. Selection/filename order does not matter. Horizontal sweeps, vertical sweeps, and multi-row sets are supported: each photo must overlap at least one other photo in one connected set. Review the entire composed result, seams, and automatic rectangular crop before choosing an output folder and saving it. The preview initially fits the whole view; use the zoom slider or pinch gesture and scrollbars to inspect seams up to full pixel resolution.

Stitching runs entirely on-device and adds no third-party or native computer-vision dependency. Sources are decoded through Windows Imaging Component with EXIF orientation applied and sRGB color management; transparency is flattened onto white. The inputs are never modified. The JPEG derivative is staged and published under a distinct ` - Panorama` name without overwriting an existing file; an existing name is incremented. The new image is indexed and revealed in the library. Embedded XMP records **every** source basename, decoded dimensions, normalized-source-to-output homography, per-channel exposure gains, stitch method, output scale, and retained crop area. Source GPS, face regions, edit recipes, and other metadata are not copied because their coordinates or meaning may no longer be valid. This workflow uses the stored still-image pixels, **not non-destructive edit recipes**; export edited photos first to include their edits.

Supported input formats are JPEG, PNG, TIFF (first frame), and BMP. RAW and video files are not supported. Each input may be at most 512 MB and is decoded to at most 2,400 pixels on its longest edge, reduced further for large selections so the combined decoded working set stays below 48 megapixels (192 MB of BGRA data). For 64 photos the longest-edge limit is 866 pixels per source. Output is uniformly reduced when necessary to stay within 16 megapixels and 32,000 pixels per side; the preview discloses the scale. Blending uses 32-row accumulation strips instead of a full floating-point canvas or repeatedly stitching an already blended image. Sources are resampled only once into the final canvas. Progress covers decoding, cached feature extraction, all-pairs overlap search, and rendering; cancellation is checked throughout.

The matcher extracts oriented binary features once per photo, checks all photo pairs, and uses RANSAC and competing-model rejection to build an overlap graph. A graph-central reference and strong overlap links place all sources in one coordinate system. Every accepted overlap is then checked against the global placement to reject inconsistent loops/drift. Disconnected photos cause an explicit error naming the unconnected files; they are never silently dropped. The crop must retain meaningful coverage of every selected source.

This is a **projective/rectilinear** stitcher for mostly static, planar or distant scenes, not a cylindrical or spherical renderer. It does **not** support full 360-degree sweeps or views crossing the projective horizon. Reflected/collapsed transforms, horizon crossings, excessive stretching, weak or concentrated matches, incompatible parallax, large exposure differences, and unsuitable crops are rejected. Dozens of overlapping frames can cover a broad rectangular view, but a large photo count alone does not make an arbitrary camera sweep geometrically safe. Repeated patterns, movement, significant lens distortion, large viewpoint changes, and residual drift can still make a result unusable. Inspect the preview before saving; there is no manual alignment/seam/crop editor or lens calibration in this workflow.
