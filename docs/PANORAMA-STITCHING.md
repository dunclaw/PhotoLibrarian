# Panorama stitching

Select **2 to 64 overlapping photos** in the grid, open the context menu, and choose **Stitch panorama**. Selection/filename order does not matter. Horizontal sweeps, vertical sweeps, and multi-row sets are supported: each photo must overlap at least one other photo in one connected set. Review the entire composed result, seams, and automatic rectangular crop before choosing an output folder and saving it. The preview initially fits the whole view; use the zoom slider or pinch gesture and scrollbars to inspect seams up to full pixel resolution.

Stitching runs entirely on-device using a minimal, bundled OpenCV 4.12.0 native module. No separate program, Python installation, service, account, model download, or network access is needed at runtime. Sources are decoded through Windows Imaging Component with EXIF orientation applied and sRGB color management; transparency is flattened onto white. The inputs are never modified. The JPEG derivative is staged and published under a distinct ` - Panorama` name without overwriting an existing file; an existing name is incremented. The new image is indexed and revealed in the library.

Embedded XMP records **every** source basename, decoded dimensions, per-channel exposure gains, projection, stitch method, output scale, and retained crop area. Projective sets record normalized-source-to-output homographies. Spherical sets instead record each camera's intrinsic and rotation matrices, the spherical warp scale, and the final cropped canvas offset; a spherical warp is not misrepresented as a homography. Camera matrices operate on decoded pixel coordinates. For a camera ray `R * inverse(K) * [x,y,1]`, spherical output coordinates are `scale * atan2(ray.x,ray.z)` and `scale * (pi - acos(ray.y / length(ray)))`, minus the recorded canvas offset. Source GPS, face regions, edit recipes, and other metadata are not copied because their coordinates or meaning may no longer be valid. This workflow uses the stored still-image pixels, **not non-destructive edit recipes**; export edited photos first to include their edits.

Supported input formats are JPEG, PNG, TIFF (first frame), and BMP. RAW and video files are not supported. Each input may be at most 512 MB and is decoded to at most 2,400 pixels on its longest edge, reduced further for large selections so the combined decoded working set stays below 48 megapixels (192 MB of BGRA data). For 64 photos the longest-edge limit is 866 pixels per source. Feature extraction uses at most 0.6 megapixels and 3,000 SIFT features per source. Output is uniformly reduced when necessary to stay within 16 megapixels, 32,000 pixels per side, and 64 million combined warped source pixels; the preview discloses the scale. Seam estimation uses a lower-resolution working set, capped at 4 million warped pixels. Full-resolution sources are warped and fed into the multiband blender one at a time, rather than retaining all full-resolution warped copies or repeatedly stitching an already blended image. Native blending needs additional memory for its output pyramids, beyond the decoded-image budget.

Progress covers decoding, feature extraction, each overlap pair, camera adjustment, seam estimation, composition, and cropping. Cancellation is checked between pairs, images, and stages and during the pixel-copy/crop loops. An individual OpenCV SIFT, bundle-adjustment, graph-cut, or blend call finishes before cancellation is observed; it is not forcibly interrupted. Failure or cancellation releases native images and buffers. Output writing and staging cleanup retain the same cancellation checks as other local export operations.

SIFT features handle resampling, orientation, and scale changes; matching checks every photo pair. Accepted overlaps require at least 12 RANSAC inliers, 30% consensus, spatial coverage, and OpenCV panorama confidence of at least 1.0. Nearly planar/translation sets use projective alignment, with similarity fitting for near-affine links to avoid underconstrained projective drift. Camera sweeps with appreciable perspective use camera rotation estimation, joint ray-based bundle adjustment, and spherical projection instead of stretching a wide sweep into a single reference photo's plane. Accepted edges are checked again against the final global geometry. Disconnected photos cause an explicit error naming the unconnected files; they are never silently dropped. The clean crop must retain meaningful coverage of every selected source.

Per-channel exposure compensation, gradient-aware graph-cut seam selection, and multiband blending handle modest local motion/parallax better than averaging the entire overlap, which can create doubled branches or buildings. A coherent second alignment displaced by more than 10% of the source's longest edge is rejected, as are global alignment disagreements, excessive exposure differences, invalid/reflected/collapsed geometry, projective horizon crossings, excessive stretching, and unsuitable crops. This is not arbitrary 3D reconstruction or a guarantee of invisible seams. Repeated patterns, large viewpoint changes, severe lens distortion, and movement across a seam can still make a result unusable. Full 360-degree wraparound/polar panoramas and calibrated lens correction are not supported. Inspect the entire preview before saving; there is no manual alignment/seam/crop editor.

## Native build and distribution

`tools\Build-Panorama.ps1` builds `native\PhotoLibrarian.Panorama` through the same Visual Studio C++/CMake toolchain already required by the RAW decoder. The first build downloads the pinned OpenCV 4.12.0 source archive (95,254,890 bytes) over HTTPS and verifies its SHA-512 in both PowerShell and CMake. Source and native build outputs are cached; unchanged native inputs skip rebuilding. The archive is a build-time dependency, **not** an additional 91 MB payload in the app.

Only `core`, `imgproc`, `features2d`, `calib3d`, `flann`, and `stitching` are statically linked into `PhotoLibrarian.Panorama.dll`, with the static Microsoft runtime. OpenCV media codecs, video/camera input, UI, Python, DNN, GPU backends, IPP, and non-free algorithms are not included. Windows x64 and ARM64 cross-builds were verified; ARM64 execution still requires an ARM64 machine. Measured release-compiled DLL sizes are approximately **5.6 MiB x64** and **3.8 MiB ARM64**, plus approximately 272 KiB of license notices. The x64 DLL imports only `KERNEL32.dll`; users do not need an OpenCV or Visual C++ runtime installation. MSBuild copies the matching DLL and `ThirdPartyNotices\Panorama.txt` through app/test/publish outputs and into MSIX packages.

OpenCV is Apache-2.0 licensed. The minimal build also contains permissively licensed FLANN (BSD), SoftFloat (BSD), fdlibm (Sun), and zlib code. The build collects OpenCV's license/copyright, zlib's license, and applicable leading license notices from the enabled modules into the packaged notice file. No `opencv_contrib` or non-free module is downloaded or compiled.

Regression coverage includes shuffled 32-frame horizontal, 24-frame vertical, and 64-frame grid mosaics; a generated four-camera, resampled, exposure-varied spherical sweep with an occlusion and known camera rays; perspective landmarks; no overlap; conflicting parallax; output geometry/budgets; native-stage cancellation/retry; byte-identical sources; and safe JPEG/XMP saving. The generated camera sweep measures reprojection error rather than accepting an image solely because the API returned success.
